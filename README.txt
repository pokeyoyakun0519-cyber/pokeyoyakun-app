PokeyoyaKun Ver.1.0.1

【修正内容】
公式情報ソースを確認しても、商品一覧へ商品が追加されない問題を修正しました。

旧仕様:
・ページの<title>だけを取得
・商品抽出は未実装
・商品一覧への自動追加なし

新仕様:
・リンク文字を解析
・バナー画像のalt文字を解析
・商品名と発売日を抽出
・商品一覧へ自動追加
・同じ商品は重複追加しない

【ポケモンカード公式サイト】
トップページの以下から取得します。
・メインバナー
・PICK UP
・商品お知らせ

【確認方法】
1. 公式情報ソースを開く
2. ポケモンカード公式トップを登録
3. 「登録ページを手動確認」
4. 商品検出件数と新規追加件数を確認
5. 商品一覧を開く
6. 発売予定商品が追加されていることを確認

【注意】
画像そのものをOCRしているのではありません。
公式サイトが画像へ設定しているalt文字と、リンク文字を利用します。

【Ver.1.1.0 商品取得方式】
1. ポケモンカード公式トップのリンク文字・画像altを解析
2. 公式商品詳細ページを最大8件だけ取得
3. 詳細ページの商品名・発売日をHTMLから抽出
4. 同じ商品を重複登録しない
5. 詳細ページが取得できない場合だけトップページ解析へ戻る
OCRは常用せず、公式HTMLの構造化された文字情報を優先します。


【Ver.1.1.1 情報の流れ】
1. 公式情報ソースから商品名・発売日・公式URLを取得

3. 新弾候補からポケモンセンターオンラインとヨドバシを検索
4. 販売・抽選情報が見つかった候補だけ商品一覧へ追加
5. 商品一覧に応募期間・結果発表・購入期限を表示

【Ver.1.24.0 RC User Edition ノートPCテスト手順】

事前準備（管理PC）:
1. ライセンスサーバーを起動し、8765番ポートで待受中であることを確認します。
2. 管理画面または管理CLIで、テスト用オンラインライセンスキーを1件発行します。
3. 公開URLの /health を外部回線から開き、ok が true になることを確認します。
   例: http://180.24.86.226:8765/health
4. release\user_installer\PokeyoyaKun_User_Setup_Ver1.24.0_RC.exeをノートPCへコピーします。

インストールとオンライン認証（ノートPC）:
1. 管理PCと同じLANは使わず、スマートフォンのテザリングなど別の回線へ接続します。
   同一LANから公開IPへ接続すると、ルーターのNATループバック非対応により
   タイムアウトする場合があります。
2. PokeyoyaKun_User_Setup_Ver1.24.0_RC.exeを実行し、インストールします。
3. ポケヨヤ君を起動します。配布版では認証サーバーURLは画面へ表示されません。
4. 「接続テスト」を押し、「ライセンスサーバーへ接続できました。」と
   表示されることを確認します。
5. 発行したオンラインキーを入力し、「オンライン認証して起動」を押します。
6. メイン画面が表示されることを確認します。

再起動・異常系の確認:
1. アプリを終了して再起動し、登録済みキーで再認証できることを確認します。
2. 管理画面でライセンスを停止し、ノートPCで再確認した際に起動が拒否される
   ことを確認します。サーバーが停止を返した場合、オフライン認証へは移行しません。
3. ライセンスを再開し、再び認証できることを確認します。
4. ノートPCを一時的にオフラインにし、ローカルキャッシュでは起動が許可されず
   フェイルクローズすることを確認します。
5. テスト終了後、Windowsの「インストールされているアプリ」から
   ポケヨヤ君をアンインストールできることを確認します。

確認ポイント:
・設定とオンラインキーは%LOCALAPPDATA%\PokeyoyaKun\configへ保存されます。
・接続失敗時は管理者側でサーバーURL、8765番ポート、Windowsファイアウォール、
  ルーターのポート転送、利用中回線を順に確認してください。
・本番公開では、応答改ざん防止のためHTTPSを必須にしてください。


【Ver.1.24.0 RC User Edition 配布セキュリティ】
・固定Administrator認証と従来のローカルライセンス判定をUser Editionから削除しました。
・ライセンス発行、停止、期限、端末数の最終判定はサーバー側だけで行います。
・配布版のサーバーURLは画面へ表示せず、devチャネルだけで変更できます。
・ビルド前の秘密情報検索と、配布後の.py、テスト、デバッグ情報混入検査を追加しました。
・従来のPyInstaller版を維持し、比較用のNuitkaネイティブビルドを追加しました。
・配布EXEのSHA-256マニフェストを生成し、起動時に単純な改ざん・破損を検査します。

残る限界:
利用者PC上のコードは完全には秘匿できず、Nuitka版も高度な解析や実行時パッチを
完全には防げません。SHA-256マニフェストもEXEと同時に書き換えられる攻撃には
耐えないため、正式配布ではWindows Authenticode署名と署名済み更新を併用してください。
また、現在の既定URLがHTTPの間は通信応答の改ざんを防げません。本番運用前に
信頼できる証明書を持つHTTPSへ移行する必要があります。サーバーURL自体はバイナリや
通信先から判別可能であり、画面で非表示にすることはURLの秘密化を意味しません。
